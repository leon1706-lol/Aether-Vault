# development

Everything here is written BY the development process FOR future development: what
the system IS, how to RUN it, what HAPPENED, and every PROBLEM found along the way.
Kept separate from the root README so that file stays short and scannable.

- `architecture.md` - what the system IS today: one contract section per subsystem
  (staging, commit, sync, merge, restore, GC, auth, transport, webui, plugins,
  release, runs/events/signing/env-snapshot/audit), system diagrams, module map,
  testing map. Living document - rewritten in place.
- `infrastructure.md` - how to RUN it: engine compose stack, environment variables,
  Protected mode, migrations, releases, PostgreSQL inspection SQL. Living document.
- `CHANGELOG.md` - the full phase-by-phase build history, oldest first. Append-only:
  past entries describe what was true AT THE TIME and are never rewritten.
- `Probleme.md` - severity-rated defect ledger (Problem -> Fix -> Verification).
  Append-only; entry numbers are permanent permalinks cited everywhere.
- `BENCHMARKS.md` - captured cross-tool results, generated by
  `av benchmark --markdown`; regenerate rather than hand-edit. Its "Perf history trend"
  section (between the `PERF-HISTORY:START`/`END` markers) is separately re-rendered by
  `scripts/append_perf_history.py` from `perf-history.json` - run that AFTER
  `av benchmark --markdown`, which overwrites the whole file.
- `perf-history.json` - append-only capture log behind the BENCHMARKS.md trend table;
  written by `scripts/append_perf_history.py`, read by `scripts/release_gate.py`'s release
  check that the version being tagged has a real capture.
- `threat-model.md` - assets, actors, trust boundaries, and a threat -> mitigation ->
  residual-risk table, with an annual-review checklist. Linked from `SECURITY.md`.
- `MEMORY.md` - the memory envelope: how to measure it, the budgets, the before/after
  table (`memory-baseline-v1.6.2.json` / `memory-scoreboard-v1.6.3.json`), every knob.
  Per-phase plan/continuation notes are deliberately NOT kept here: a phase's record is
  its CHANGELOG entry plus Probleme.md; temporary planning files live in `todo.md`.
- `logo.png` - used by the root README banner.

More development-process documents can live here over time.
